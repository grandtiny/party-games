# 血染钟楼房间页布局重设计

**日期**：2026-07-23
**范围**：`apps/web/src/games/clocktower/`（仅血染钟楼模块，不触碰平台层/后端/其他游戏）
**目标**：解决房间页"太长、手机端操作繁琐"的问题，提升手机和桌面两端的游戏体验。

## 问题背景

实测第 4 天讨论阶段（信息最密集阶段）的页面高度：

| 设备 | 总高度 | 滚动屏数 | 主要占比 |
|---|---|---|---|
| 桌面（1440×1346） | 2368px | 1.76 屏 | 圆桌 771px(33%)、聊天 370px(16%) |
| 手机（375×812） | 2119px | ~2.6 屏 | 圆桌 545px(67% 超半屏) |

**核心矛盾**：白天讨论阶段，玩家最常用的「聊天」和「申请提名」被压在页面最底部，而占半屏的圆桌、身份卡、事件记录挡在中间，玩家需反复上下滚动。

## 设计决策（已与用户确认）

1. **使用场景**：手机 + 桌面并重
2. **圆桌处理**：始终显示但缩小（手机约 40% 屏）
3. **聊天与操作**：底部 Tab 切换（同一区域按需切换）
4. **次要信息**：身份卡、事件记录、恢复码全部收进 Tab/顶栏
5. **Tab 配置**：随游戏阶段动态变化
6. **布局方案**：方案 A（阶段感知底部 Tab + 主体留白）

## 整体架构

### 新页面骨架（第 1 节）

根容器从 `min-height: 100vh` 改为 **`height: 100dvh; overflow: hidden`**，整页不再滚动，只有 Tab 内容区独立滚动。

```
.app-shell--clocktower (height: 100dvh, flex column, overflow:hidden)
├── .topbar                          (顶栏，原有，actions 区改造)
├── .ct-room-main (flex:1, overflow:hidden)   ← 新增包裹层
│   ├── .ct-stage-bar                (统一阶段横幅)
│   ├── .ct-table-mini               (圆桌缩小版)
│   └── .ct-tab-panel (flex:1, overflow:auto)  ← Tab 内容区，独立滚动
└── .ct-tabbar                       (底部 Tab 栏，固定)
```

**移动端安全区**：`.ct-tabbar` 加 `padding-bottom: env(safe-area-inset-bottom)` 适配 iPhone home 条。

### 桌面端双栏（第 6 节，≥900px）

宽屏下 `.ct-room-main` 改为横向 flex：

```
.ct-room-main (≥900px: flex-direction: row)
├── 左栏 (flex:1)
│   ├── .ct-stage-bar
│   └── .ct-table-mini (圆桌，桌面端更大，7-10人用标准座位)
└── 右栏 .ct-tab-panel (固定宽 420-480px，独立滚动)
```

底部 Tab 栏在桌面端**保留不变**（固定底部 4 列，保持两端交互一致）。

**断点**：`min-width: 900px`。圆桌尺寸：手机约 320px（dense 模式），桌面约 500px（标准模式）。

## 顶栏改造（第 3 节）

### actions 区结构

```
[资料 BookOpen]  [身份 Eye（仅游戏中）]  [连接状态 ●在线]
```

### 身份入口按钮

- 仅当 `view.self.privateGame` 存在时渲染（大厅阶段无身份，不显示）
- 图标 `Eye`，位于资料按钮与连接状态之间
- **交互**：按住（pointerdown）显示身份浮层，松开（pointerup/pointerleave）隐藏——保留私密性，与现有 `RoleReveal` 的 `onPointerDown/onPointerEnd` 逻辑一致
- **浮层**：绝对定位出现在按钮下方，半透明深底 + 金边，内容为角色名/阵营/能力
- **确认身份按钮**：role-reveal 阶段移入「身份」Tab 内容区

### 恢复码

`.session-strip`（恢复码条）移除，恢复码放进**「身份」Tab** 内（与身份信息同属个人私密信息）。

### 房间码

`.room-summary`（房间码条）移除，房间码 + 复制功能收进顶栏标题（顶栏标题"房间 QBZDV5"点击或加复制图标即可复制）。

## 阶段横幅（第 5 节）

`.ct-stage-bar` 主体顶部固定横幅，约 56px 单行：

```
┌─────────────────────────────────────┐
│ ☀ 第 4 天 · 讨论    6 人存活  [提名▸] │
└─────────────────────────────────────┘
```

**内容**（左到右）：
- 阶段图标 + 名称：☀ 白天 / 🌙 夜间 / 🗳 提名 / 📜 复盘
- 关键计数：白天"X 人存活"，提名"已提名 X"，投票"当前票数"
- 快捷操作入口：右上角小箭头，点击跳转到对应 Tab（讨论阶段"提名▸"跳操作 Tab）

**合并来源**：吸收 `.day-banner`（存活数）、`.night-panel__heading`（夜间标题）、`.room-summary` 的 phase-label。原组件中这些标题部分移除，只保留内容主体。

**夜间特殊处理**：横幅只显示"🌙 第 N 夜 · 保持安静"，不暴露具体行动（隐私）。

## 圆桌缩小版 `.ct-table-mini`（第 4 节）

### 缩小策略

| 元素 | 处理 |
|---|---|
| panel 标题栏（"圆桌座位" + 入座数） | **移除**（入座数已在阶段横幅/Tab 显示） |
| 圆环本体（含魔法阵） | **等比缩小**，金边/魔法阵/桌心全保留 |
| 座位（头像+名字+状态） | **紧凑模式**（强制 `is-dense`：头像 42px、名字 10px） |
| 候场玩家条 `.waiting-players` | **移除**——大厅阶段候场玩家在「准备」Tab 列出 |
| 选中玩家操作条 `.table-player-actions` | **保留**——白天提名/猎手选择核心，叠加在圆环下方 |

### 圆环自适应

`.ct-table-mini` 用 `flex: 1` 占主体剩余空间，圆环用 `aspect-ratio: 1` + `max-height/max-width: 100%` + `margin: auto` 居中自适应。

### 桌面端

≥900px 时圆桌不强制 dense，7-10 人用标准座位（头像 50px），尺寸更大（约 500px）。

### 交互全部保留

入座/离座、夜间选人（is-selectable 金圈）、白天选目标（table-player-actions）、投票状态高亮——缩小版全部保留，仅视觉缩小。

## 底部 Tab 栏（第 2 节）

### 结构

```
.ct-tabbar (固定底部，flex/grid，2-4 列)
├── [button 图标+标签+未读红点] ×N
```

每个 Tab 按钮：lucide 图标 + 2 字中文标签，激活态金底高亮，符合哥特主题。

### 各阶段 Tab 配置

| 阶段 | Tab 配置 | 默认激活 |
|---|---|---|
| lobby（大厅） | `[准备]` | 准备 |
| role-reveal（确认身份） | `[身份]` | 身份 |
| first-night / night（夜间） | `[行动] [魔典] [聊天]` | 行动 |
| day（白天讨论） | `[操作] [聊天] [事件]` | 聊天 |
| nominations（提名） | `[操作] [聊天] [事件]` | 操作 |
| voting（投票） | `[投票] [聊天]` | 投票 |
| game-over（结束） | `[复盘] [聊天]` | 复盘 |

### Tab 内容来源（复用现有组件，不重写）

| Tab | 内容 | 现有组件 | 显示条件 |
|---|---|---|---|
| 准备 | 准备/开始按钮 | `.room-actions` | lobby 阶段 |
| 身份 | 身份揭示卡 + 恢复码 | `RoleReveal` + recoveryCode | role-reveal 阶段，或游戏中（顶栏身份入口的展开态） |
| 行动 | 夜间私密行动面板 | `NightPanel` | night/first-night，玩家有 nightAction 时 |
| 魔典 | 邪恶阵营信息列表 | `NightResult`（evil-team/grimoire） | **仅邪恶阵营玩家**夜间显示（善良阵营无此 Tab） |
| 操作 | 白天裁定（申请提名/猎手） | `DayControlPanel` | day/nominations 阶段 |
| 投票 | 顺时针投票面板 | `VotingPanel` | voting 阶段 |
| 聊天 | 公屏/私聊 | `ChatPanel` | day/nominations/voting/night 阶段（夜间私聊锁定的逻辑保留） |
| 事件 | 公共事件记录 | `PublicEventPanel` | day/nominations/voting 阶段 |
| 复盘 | 身份公开+时间线+夜间审计 | `GameOverPanel` 复盘部分 | game-over 阶段 |

**Tab 动态渲染规则**：每个阶段的 Tab 列表在渲染前先过滤掉"不满足显示条件"的 Tab。例如善良阵营玩家在夜间只看到 `[行动] [聊天]`，邪恶阵营玩家看到 `[行动] [魔典] [聊天]`。

**原则**：Tab 内容复用现有组件，只改变挂载位置（垂直堆叠 → Tab 切换），组件内部逻辑/props/事件全部不动。

### 智能默认与未读提示

- 进入新阶段自动激活最相关 Tab（如表格"默认激活"列）
- 聊天 Tab：有新消息且非激活时显示红点
- 操作/行动 Tab：有待处理操作（可申请提名、夜间需行动）时显示红点

## 实现约束

- **作用域**：所有新样式以 `.app-shell--clocktower` 为前缀，主题变量集中在 `theme.css`
- **零业务逻辑改动**：组件 props/state/socket 事件不变，只调整渲染挂载位置
- **不触碰**：平台层 `styles.css`（除非血染作用域覆盖被压制）、后端、德州扑克、`fonts.css`
- **可复用**：新增布局组件（CtTabBar、CtStageBar 等）放 `apps/web/src/games/clocktower/components/`

## 风险

- **Tab 切换的滚动状态丢失**：切换 Tab 后内容区滚动位置重置——可接受（每个 Tab 进入时滚到底部，如聊天）
- **桌面双栏在中等宽度尴尬**：900px 断点下平板竖屏走单栏、横屏走双栏，需测试 768-1024px 区间
- **身份浮层在小屏遮挡**：浮层需确保不超出视口，必要时手机端改为底部抽屉式弹出
