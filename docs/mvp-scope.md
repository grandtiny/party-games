# 聚会游戏站 MVP 边界

## 当前目标

- 首页是游戏大厅，血染钟楼与德州扑克为平级入口。
- 当前优先实现血染钟楼“暗流涌动”。
- 系统承担说书人职责，所有参与者都作为玩家。
- 本阶段只保证本地构建和 Docker 部署，不处理云服务器、域名和 HTTPS。

## 已确认原则

- 服务端持有权威状态，客户端只接收玩家有权查看的投影视图。
- 核心规则使用可重放状态机和带种子的随机源。
- 本地说书人策略必须独立运行；大模型只作为可选适配器。
- 公共信息同步到每位玩家手机，不依赖公共电视或平板。
- 提名和投票遵循原版顺时针公开投票。
- 平衡用于开局组合和局部裁定质量，不实时扶弱或控制胜率。

## 第一实现阶段

- 游戏大厅与两个平级入口。
- 暗流涌动房间创建、口令加入、圆桌入座/离座、准备和恢复会话。
- 5 到 15 人官方角色数量。
- 服务端生成角色组合、酒鬼伪装、占卜师红鲱鱼和恶魔伪装。
- 私密身份投影；普通玩家网络响应不包含其他玩家身份。
- SQLite 快照和追加事件，为后续完整状态机提供恢复基础。
- 身份确认后按官方顺序执行完整首夜，并自动进入第一天。
- 首夜覆盖邪恶阵营信息、投毒者、首夜信息角色、占卜师、管家和间谍。
- 白天线下讨论，所有公共状态同步到每位玩家手机。
- 多数申请进入或结束提名；每名存活玩家每天最多提名一次，每名玩家每天最多被提名一次。
- 从被提名者开始按实体座位顺时针公开锁票，支持死亡票和管家投票限制。
- 猎手公开声明、贞洁者、圣徒、小恶魔、猩红女郎、镇长和两人存活等基础死亡与胜负链。
- 公屏和一对一私聊；夜间锁定发送，消息保留 24 小时且不进入规则复盘。
- 玩家可在血染钟楼各阶段打开本地角色与规则资料，官网仅作为可选来源链接。
- 普通夜晚按官方顺序执行投毒者、僧侣、小恶魔、守鸦人、共情者、占卜师、送葬者、管家和间谍行动。
- 士兵免疫、镇长夜间转移、小恶魔自杀传位、酒鬼伪装行动及中毒错误信息使用带种子的本地裁定。
- 黎明公布昨夜死亡结果，重置每日提名状态并进入下一天；核心状态机可以继续后续日夜循环。
- 游戏结束后公开完整身份、跨天公共事件和夜间动作记录；房主可以保留原房间、座位和恢复码发起新一局。
- 夜间选择、提名和猎手声明可以直接在圆桌头像上操作。
- SQLite 使用顺序迁移版本并兼容旧状态；已覆盖十五人重复重连和投票临界重连。
- 规则问答默认使用本地资料，可选调用 OpenAI 兼容接口；模型失败时自动降级且不参与游戏裁定。
- 首页提供受管理员密码保护的系统设置页；首次访问创建密码，可持久化模型配置、测试连接并修改管理员密码。

## 当前验证覆盖

- 自动生成 5 到 15 人配置，确认全部 22 个暗流涌动角色都进入测试样本。
- 44 组多轮对局分别重复运行两次，检查状态机不阻塞、同种子结果一致、存活恶魔最多一名且胜负都有明确原因。
- 显式覆盖间谍和隐士的双向登记、酒鬼伪装行动、中毒失效、镇长转移和小恶魔自杀传位。
- 普通夜晚进行中关闭并重新打开 SQLite 仓库后，夜序位置、房间版本和玩家私密行动保持一致。
- 游戏结束后仅在公共投影中公开全部身份，重开后清除旧身份、复盘和聊天并生成新随机种子。
- 旧数据库自动迁移到当前版本；十五名玩家连续五轮断线重连后房间成员和连接状态保持一致。
- 投票意图在锁票前断线并重连后保持，最终锁票结果不丢失。
- 本地规则问答、大模型成功答复和大模型故障降级均有自动测试。

- 德州扑克已完成规则内核、服务端权威合法行动、当前手结算记录、积分桌离桌/回桌、淘汰赛手动或自动盲注、排名/重赛、按行动顺序逐步广播的确定性单人 AI 对局及 2/3/6/9 人规则回归，默认通过功能开关保持关闭。
